# MVP 验收合同（冻结版）

- 合同版本：`MVP-1`
- 冻结日期：`2026-07-19`
- 验收方式：五项全部通过才算完成；`partial` 等同于未通过
- 变更规则：未经用户明确同意，不增加公司、产业层级、模型、界面或自动化交易范围

本合同只回答“第一版是否可用于可审计研究”。界面美观不在验收范围内。

## AC1：统一公司与证券主表

通过条件：

1. `company_id` 唯一；同一家公司不会因 A/H/ADR 等不同证券被重复建档。
2. 每条证券记录唯一对应一个 `company_id`；`(ticker, market)` 唯一。
3. 每家公司恰有一个 `is_primary=true` 的研究主证券，其余为映射证券。
4. 市场、币种、证券类型一致：至少保证 `A→CNY`、`H→HKD`、`US→USD`。
5. 不存在孤儿证券、空 ticker、空市场、空币种或空证券类型。
6. 随机抽查 A/H/US 映射时，证券名称、公司实体和上市地能回到交易所或公司披露。

阻断条件：任何重复映射、错币种、错市场或同一实体被当成两家公司。

## AC2：产业链关系可追溯

通过条件：

1. 关系表至少有 10 条，才能无放回抽取 10 条。
2. 每条关系必须有非空 `source_id`、`disclosed_at`、`valid_from`、`confidence`。
3. `source_id` 能连接到原始披露材料；只有搜索结果、媒体转述、首页或聚合索引不算原始披露。
4. 原始材料必须保留精确定位信息，例如 PDF 页码、公告章节或网页段落。
5. 原始材料需满足以下任一条件：官方不可变文件链接；或本地归档副本加 SHA-256。
6. `disclosed_at` 表示市场最早可获得该关系的时间，不能用后来的确认日期回填历史。
7. 以固定随机种子 `mvp-v1` 无放回抽取 10 条，人工复核结果必须是 `10/10 PASS`；一条失败即 AC2 失败。

抽查记录至少包含：

```text
edge_id, source_company, relation_type, target_company, product,
source_id, source_url, disclosed_at, valid_from, source_locator,
archived_path_or_sha256, auditor_result, auditor_note
```

## AC3：范围严格等于 30 家

通过条件：

1. 公司数必须恰好等于 30，不是“至少 30”。
2. 产业层级集合必须严格等于：`云厂商`、`GPU/ASIC`、`HBM与先进封装`、`网络与光互联`。
3. 证券映射不会增加公司计数。
4. 第一版不加入电力、冷却、服务器或其他公司。

## AC4：能够回答三个投资问题

三个问题必须都能在指定 `as_of_date` 下重复查询，并展示使用的数据截止时间和证据来源。

### Q1：CapEx 上调后的直接与二级受益者

输入：公司、CapEx 事件、`as_of_date`。

输出至少包含：受益公司、直接/二级层级、传导路径、产品、关系披露时间、置信度和来源。查询不得使用 `disclosed_at > as_of_date` 的关系。

### Q2：真实收入暴露与概念映射

输出必须按统一规则区分：`直接-高`、`直接-中`、`直接-低`、`间接`、`待核验`，并展示收入/订单证据、证据期间、来源和最强反方。只有产品关系而没有订单、收入或客户证据的公司不能标为高直接暴露。

### Q3：基本面是否快于盈利预期和股价定价

同一证券、同一截止日下至少比较：经营指标变化、收入/EPS 一致预期修正、估值或股价变化。缺少任一类数据时只能返回“数据不足”，不能进入观察名单。

阻断条件：使用未来披露、不同期间错配、不同币种未说明、把相关性写成因果，或没有证据却给出“未充分定价”结论。

## AC5：可重复生成五个研究输出

必须存在一个文档化命令，从种子数据和更新数据重新生成：

1. `supply_chain_master.csv`
2. `capex_tracker.csv`
3. `profit_transmission.csv`
4. `expectation_gap_watchlist.csv`
5. `data_quality_report.json`

要求：

- 输出写入带 `as_of_date` 的独立目录，不覆盖历史版本。
- 删除该输出目录后重新运行，仍能生成五个文件。
- 相同输入与相同 `as_of_date` 的内容哈希一致；生成时间等非研究字段不得破坏确定性。
- 数据质量报告至少包含行数、主键重复、必填空值、孤儿引用、未来日期、币种/市场规则和 10 条关系抽查结果。
- 任一输出失败、为空、使用未来数据或 DQA 失败，整次构建返回非零退出码。

## 明确不做

- GNN
- Neo4j 复杂迁移
- Transformer 预测
- 多 Agent 自动决策
- 全市场覆盖
- 自动交易
- 以静态网页或 UI 作为验收物

## 完成后的 Review 顺序

1. 代码层：确定性、测试、失败退出码、无隐藏网络依赖。
2. 数据结构层：粒度、主键、关联覆盖、时间字段、币种与版本。
3. 研究逻辑层：未来函数、收入暴露定义、预期差计算、最强反方。

在三层 review 通过前，不做界面优化。
