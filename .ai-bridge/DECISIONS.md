# 关键决策

## 已采用的选择

### 1. CSV 源层 + DuckDB 查询层

- 原因：首版数据量小，需要可读、可 diff、可重建；DuckDB 足以支持本地研究查询。
- 代价：尚无正式 migration、并发服务和增量摄取机制。
- 未采用：PostgreSQL、Neo4j。当前规模下会增加运维和抽象成本。

### 2. 公司实体与证券分离

- `company_master` 表示经济实体；`security_master` 表示上市证券。
- 原因：避免 A/H/ADR 被重复当成不同公司，并保留市场、币种和证券类型差异。
- 技术债务：证券映射本身尚未拥有逐条来源与披露日期。

### 3. 先冻结 30 家和四层

- 原因：先验证投资研究链条，而不是扩大成永远填不完的产业百科。
- 未采用：电力、冷却、服务器和全市场覆盖。它们不是被否定，而是被推迟到 MVP 之后。

### 4. 关系必须证据化，不允许模型猜测

- 每条关系需要 `source_id`、`disclosed_at`、`valid_from`、`confidence`。
- `source_evidence` 进一步保存定位、归档路径、SHA-256 和人工结论。
- 原因：避免未来函数、错误关系和无法复核的概念映射。

### 5. 固定种子抽查 10 条

- 使用 `mvp-v1` 对排序后的 edge ID 无放回抽样。
- 原因：验收可以重复，且一条失败即 AC2 失败。
- 技术债务：当前恰好只有 10 条关系，因此抽样等于全量检查；扩边后才真正体现抽样。

### 6. 不完整评分不进入排名

- 五项暴露评分任一缺失，`opportunity_scores` 不产生记录。
- 原因：拒绝用空值或模型臆测制造“未充分定价”排序。

### 7. `disclosed_at` 作为当前 point-in-time 闸门

- 当前含义：该来源或关系在公开市场最早可获得的自然日。
- 原因：第一版至少阻止使用未来日期。
- 技术债务：没有时间、时区、采集到达时间和数据供应商修订版本；不能支持严格日内研究。

## 已放弃或推迟的替代方案

- Neo4j/GNN：关系数量不足，不能证明会提升研究结论。
- Transformer 预测：缺少稳定标签、历史版本和基准。
- Web UI：不属于 MVP 验收条件。
- 自动数据抓取与自动交易：在数据语义和回测闸门完成前风险过高。
- 全量公司自动分类：会放大来源不完整和 LLM 概念映射问题。

## 当前技术债务

1. Git 历史从首次公开提交开始，无法追溯提交前的逐步实施 diff。
2. 没有统一 pipeline/build 命令；AC5 尚未完成。
3. 日期粒度不足，缺 `first_available_at` 和 revision lineage。
4. schema 主要依赖应用层 DQA，数据库未建立完整外键约束。
5. CSV 是全量重载；没有增量、水位、幂等批次和失败恢复记录。
6. 研究快照和证券映射的来源覆盖弱于供应链关系。
7. 测试集中于结构和闸门，尚无外部数据集成或 point-in-time 查询集成测试。
